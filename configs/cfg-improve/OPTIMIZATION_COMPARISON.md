# GFLOPs 优化配置对比

## 📊 配置参数对比

| 参数 | 原始 (40.7G) | Lite (~27G) | Ultra (~22G) |
|------|-------------|-------------|--------------|
| **特征维度** | 160 | 112 (-30%) | 96 (-40%) |
| **Transformer hidden_dim** | 640 | 448 (-30%) | 384 (-40%) |
| **dim_feedforward** | 640 | 448 (-30%) | 384 (-40%) |
| **C2f_Block 层数** | 2 | 1 (-50%) | 1 (-50%) |
| **mlp_ratio** | 4.0 | 3.0 (-25%) | 2.5 (-37%) |
| **num_layers** | 3 | 3 | 2 (-33%) |
| **num_points** | [3,6,3] | [2,5,2] (-17%) | [2,4,2] (-33%) |
| **Decoder hidden_dim** | 160 | 112 (-30%) | 96 (-40%) |

## 🎯 优化策略

### 1. **特征维度优化** (最大影响)
- **Lite**: 160 → 112，降低 30% 计算量
- **Ultra**: 160 → 96，降低 40% 计算量
- **影响**: 所有 PSConv、MFM、C2f_Block 的计算量

### 2. **Transformer 参数优化**
- **hidden_dim**: 640 → 448/384
- **dim_feedforward**: 640 → 448/384
- **影响**: Transformer 注意力机制和 FFN 的计算量

### 3. **C2f_Block 优化**
- **层数**: 2 → 1（降低 50%）
- **mlp_ratio**: 4.0 → 3.0/2.5
- **影响**: 每个尺度的特征处理计算量

### 4. **Decoder 优化**
- **num_layers**: 3 → 2（Ultra 版本）
- **num_points**: [3,6,3] → [2,5,2] / [2,4,2]
- **hidden_dim**: 160 → 112/96
- **影响**: 多尺度融合的解码器计算量

## 📁 配置文件

1. **dfine-n-C2f-IDWB-MFM-LSK-lite.yaml** (~27 GFLOPs)
   - 平衡性能与速度
   - 推荐作为主要优化版本

2. **dfine-n-C2f-IDWB-MFM-LSK-ultra.yaml** (~22 GFLOPs)
   - 极致轻量化
   - 适合资源受限场景

## 🔍 预期 GFLOPs 估算

- **原始版本**: 40.7 GFLOPs
- **Lite 版本**: ~27 GFLOPs (降低 34%)
- **Ultra 版本**: ~22 GFLOPs (降低 46%)

## 💡 使用建议

1. **优先测试 Lite 版本**：在保持较好性能的同时显著降低计算量
2. **如果 Lite 仍不够轻量**：使用 Ultra 版本
3. **建议验证**：通过实际训练验证 mAP 性能损失
